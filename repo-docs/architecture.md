# Architecture

How the workspace is organized and where the boundaries are. The product decisions behind this are
in [SPEC.md](../SPEC.md) §4, §5 and §13.

```text
                     Consumer applications (shell, hosted MFEs, standalone apps)
                                         |
                                         v
                                  @tecton-mui/ui
           ┌────────────────────────────┼─────────────────────────────┐
           v                            v                             v
  Passthrough modules           Hand-written modules            styles/ (Tecton theme)
  (generated by                 Icon, LocalizationProvider,     ThemeProvider, createTheme,
   pnpm inventory)              DataGrid, range pickers,        mode store, SSR, RTL
           |                    RichTreeView                          |
           v                            |                             v
  @mui/material, @mui/lab,              v                     styles/tecton/generated/**
  @mui/x-* Community          @mui/x-* Community public APIs   assets/tecton/**
                                                                      ^
                                                                      | emit (build time)
                                                       packages/tecton-adapter
                                                       vendor/<version>/ (UMD + map + CSS + fonts)

  apps/docs ──> @tecton-mui/ui (TypeScript sources)       packages/mcp ──> @mui/mcp (pinned)
```

## Packages

| Package                        | Kind                 | Depends on                                           |
| ------------------------------ | -------------------- | ---------------------------------------------------- |
| `@tecton-mui/ui`               | Published library    | MUI Core/Lab/X Community, Base UI, Emotion, date-fns |
| `@tecton-mui/tecton-adapter`   | Private build tool   | Node.js only; writes into `packages/ui`              |
| `@tecton-mui/mcp`              | Published dev tool   | `@mui/mcp` (exact pin)                               |
| `@tecton-mui/docs`             | Private static site  | `@tecton-mui/ui`, TanStack Router, MDX, Pagefind     |
| `@tecton-mui/e2e-harness`      | Private test app     | `@tecton-mui/ui`                                     |
| `@tecton-mui/consumer-fixture` | Private test fixture | `@tecton-mui/ui` (through its built `exports`)       |

Dependency rules (SPEC §4.1):

- React and React DOM are **peer** dependencies of the UI package.
- MUI, Base UI (`@base-ui/react`, for the number fields), Emotion, `stylis`/`@mui/stylis-plugin-rtl`,
  `clsx` and `date-fns` are runtime dependencies of the UI package, pinned to exact versions. Other
  date libraries (`dayjs`, `luxon`, `moment`) are not. Consumers install them when they use the
  matching adapter subpath.
- Tecton is not a runtime dependency. The adapter copies normalized Tecton code and assets into the
  UI package at build time.
- Documentation tooling (TanStack, MDX, Pagefind, react-docgen-typescript) is used only by
  `apps/docs`. The MCP relay is not a dependency of any application or of the UI package.

## `packages/ui`

```text
packages/ui/
├── src/
│   ├── index.ts                 # root barrel (generated)
│   ├── <Module>/index.ts        # passthrough (generated, AUTO-GENERATED marker) or hand-written
│   ├── internal/passthrough/    # generated re-exports of lowercase MUI utility modules (root barrel only)
│   ├── internal/range-pickers/  # shared range picker implementation + SUPPORT.md
│   ├── internal/tab-strip/      # scrolling tab strip of AppBarTabs
│   ├── internal/overflow/       # actions that collapse into ⋮, shared by AppBarActions and HeadingActions
│   ├── DataGrid/                # unified Data Grid
│   ├── RichTreeView/            # unified Rich Tree View + SUPPORT.md
│   ├── Icon/, LocalizationProvider/
│   └── styles/                  # @tecton-mui/ui/styles
├── assets/tecton/               # generated: tokens.css, fonts.css, icons.css, fonts, provenance.json
├── scripts/build.mjs
└── THIRD_PARTY_NOTICES.md
```

### Export surface

`tooling/compatibility/generate-exports.mjs` (`pnpm inventory`) reads the module lists of the
pinned `@mui/material`, `@mui/lab`, `@mui/x-date-pickers` (plus the `AdapterDateFns`,
`AdapterDayjs`, `AdapterLuxon` and `AdapterMoment` subpaths), `@mui/x-tree-view` and `@mui/x-chat`
packages. `@mui/x-chat` lists its modules in its `exports` map, not its root index, so the script
reads them from there. Its `headless` module (provider, hooks, adapter and message types) becomes
the `ChatHeadless` subpath: its `ChatMessage` and `ChatConversation` types share names with
components, so the root barrel cannot carry them. `@mui/x-data-grid` is exposed only through the
hand-written `DataGrid` module. The script generates:

- **Passthrough modules**, `src/<Module>/index.ts`, each starting with
  `// AUTO-GENERATED by tooling/compatibility/generate-exports.mjs`. A passthrough re-exports the
  upstream module (`export *`) and its default export. For MUI X modules, which export components
  by name only, it adds the conventional default export (`export { DatePicker as default }`).
  Lowercase utility modules (models, hooks, locales and so on) collide across packages. They go to
  `src/internal/passthrough/<pkg>_<module>/` and are reachable through the root barrel only.
- **The root barrel** `src/index.ts`: explicit, de-duplicated named re-exports. When two modules
  export the same name, the first one keeps it and the collision is recorded. Values that exist
  only in declarations (not at runtime) are dropped and recorded.
- **The `exports` map** in `packages/ui/package.json`: `.`, `./styles`, the CSS entry points and
  one subpath per component module. Each JS entry has three conditions:
  `@tecton-mui/source` (TypeScript source, used inside the workspace), `types` and `default`
  (`dist/`).
- **`tooling/compatibility/export-inventory.json`**: pinned versions, custom modules, subpaths,
  included upstream modules (with `overriddenBy` when a hand-written module replaces one), excluded
  upstream modules with reasons (for example deprecated Lab stubs, Material `styles` and `Icon`),
  root collisions and declaration-only values. Review this file's diff in every MUI upgrade PR.

Of the date adapters, only `AdapterDateFns` is in the root barrel; the others are subpaths only,
because they need date libraries that are not dependencies. `AdapterDateFnsV2` (date-fns v2) is not
generated, because the package pins date-fns v4.

**Hand-written modules** are directories under `src/` (other than `styles` and `internal`) whose
`index.ts` lacks the marker. They take precedence over a passthrough of the same name and are
listed as `customModules` in the inventory. Today: `Icon`, `LocalizationProvider`, `DataGrid`,
`RichTreeView`, the range pickers (`DateRangePicker`, `TimeRangePicker`, `DateTimeRangePicker` and
their `Desktop*`, `Mobile*` and `Static*` variants), `DateRangeCalendar`,
`MultiInputDateRangeField`, the `SingleInput*RangeField` fields, `NumberField`/`NumberSpinner`
and `NumberSlider`/`NumberRangeSlider` (Base UI number field with Material form components; shared
code, including the sliders' drag bar, in `internal/number-field/`),
`Menubar` (Base UI menubar and menu; one module exporting the `Menubar*` parts), `ActionBar`
(the Tecton tool palette composed from Material components; one module exporting the `ActionBar*`
parts) and `ColorSwatchControl` (the Tecton color input on a native `<input type="color">`).

`pnpm inventory:check` fails if any generated output is stale.

### `styles/`

| File                           | Role                                                                                                                                                                      |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `index.ts`                     | Public `@tecton-mui/ui/styles`. Re-exports `@mui/material/styles`, replacing `ThemeProvider` and `createTheme`, and adds the Tecton APIs                                  |
| `ThemeProvider.tsx`            | MUI `ThemeProvider` with the Tecton theme for the shared mode. `themeOptions`, `theme`, `direction`. Renders no DOM. Installs the input focus tracker and the modal layer |
| `modalLayer.ts`                | Page-level modal layer: modals of different library copies/versions (MFEs) stack like one copy's (`inert` below the top, page-wide scroll lock). Newest protocol runs     |
| `createTheme.ts`               | `createTheme` starting from the Tecton defaults; `getDefaultTheme(mode, direction)` caches the default themes                                                             |
| `modeStore.ts`                 | `useSyncExternalStore` bridge to Tecton's page-wide theme manager (shared on `globalThis`); `initTecton`, `useTectonMode`, `getThemeManager`                              |
| `ssr.tsx`                      | `TectonModeScript` / `getTectonModeScript` (sets `data-theme` before paint) and `TectonTokensStyle` (server-rendered tokens with marker)                                  |
| `rtl.ts`                       | Lazily created shared Emotion cache with `@mui/stylis-plugin-rtl`                                                                                                         |
| `tecton/index.ts`              | Internal Tecton entry for the rest of the package. `buildTectonTheme(mode, options)`. Only it, the compat layer and `ssr.tsx` (tokens string) import `generated/**`       |
| `tecton/compat.ts`             | Documented runtime corrections between Tecton 0.11.2 and the pinned MUI release                                                                                           |
| `tecton/compatChatMarkdown.ts` | Layout of Markdown inside chat messages (tables, quotes, lists, headings, task lists); merged into `MuiChatMessage` in `compat.ts`                                        |
| `tecton/compatChat.ts`         | Theme corrections for MUI X Chat (Tecton has no chat styles): Tecton icons, focus rings, monospace code, avatar fill, timestamp contrast. Never imports `@mui/x-chat`     |
| `tecton/augmentations.ts`      | MUI module augmentations for Tecton-specific props and variants                                                                                                           |
| `tecton/generated/**`          | Emitted by the Tecton adapter. Never edit                                                                                                                                 |

See [tecton-integration.md](./tecton-integration.md).

### Advanced components

All three are built on public MUI X Community APIs only. They share these design rules (see
[AGENTS.md](../AGENTS.md) §7 and §8):

- With no advanced props, the component behaves like the Community component.
- Each feature is a separate module with its own tests.
- High-frequency interaction state lives in small external stores read with narrow selectors.

**DataGrid** (`src/DataGrid/`):

```text
DataGrid/
├── index.ts                  # export * from '@mui/x-data-grid' + unified DataGrid and types
├── DataGrid.tsx              # composes the pipeline and renders the Community DataGrid
├── public-types.ts           # DataGridProps = Community props + DataGridAdvancedProps
├── useGridAdvancedApiRef.ts
├── core/                     # store, context, row pipeline, tree, columns, controlled state
├── mui-community-adapter/    # column building, cells, slots for the Community grid
├── features/
│   ├── sorting-filtering/    # multi-sort, multi-filter, header filters
│   ├── pinning-reordering/   # column/row pinning and drag reordering
│   ├── tree-data/
│   ├── grouping-aggregation/ # row grouping, aggregation functions
│   ├── selection-clipboard/  # cell range selection, clipboard paste
│   ├── server-data/          # data source, cache, lazy loading
│   └── undo-redo/            # history stack
└── tests/
```

Master/detail panels are implemented in `DataGrid.tsx`, `core/context.ts` and
`mui-community-adapter/` (`buildColumns.tsx`, `cells.tsx`). They do not have their own `features/`
folder yet.

**Range pickers** (`src/internal/range-pickers/`): one shared implementation (`createPicker.tsx`,
`RangePicker.tsx`, `DateRangeCalendar.tsx`, `TimeRangeView.tsx`, `DateTimeRangeView.tsx`, `fields/`,
`validation.ts`, `highlightStore.ts`), exposed through thin per-component modules such as
`src/DateRangePicker/`. The supported surface is in its
[SUPPORT.md](../packages/ui/src/internal/range-pickers/SUPPORT.md).

**RichTreeView** (`src/RichTreeView/`): wraps the Community `RichTreeView`, with feature engines in
`features/{core,reordering,lazy-loading,virtualization}`. See its
[SUPPORT.md](../packages/ui/src/RichTreeView/SUPPORT.md).

### Build

`packages/ui/scripts/build.mjs`:

1. Runs `tsc -p tsconfig.build.json`: per-file ESM plus `.d.ts` into `dist/`. Modules are kept
   separate, which preserves tree shaking. Tests are excluded.
2. Copies `assets/tecton/{tokens,fonts,icons}.css` and the font files to `dist/styles/`.
3. Writes `dist/styles/global.css` (fonts + icons + tokens) and `dist/styles/components.css`
   (intentionally empty: Tecton ships no static component CSS).
4. Fails if `THIRD_PARTY_NOTICES.md` is missing.

`package.json` declares `"sideEffects": ["*.css"]`, so bundlers keep the CSS imports and tree-shake
everything else.

### Source condition

Inside the workspace, the Vitest config, the docs portal Vite config and the harness Vite config
resolve `@tecton-mui/ui` with the custom `@tecton-mui/source` export condition, which points at
`src/**/*.ts`. No UI build is needed for tests, docs or the harness. Only `pnpm test:bundle` and
published consumers use `dist/`.

## `packages/tecton-adapter`

A build-time tool. Nothing in it runs in consumer applications. See
[tecton-integration.md](./tecton-integration.md).

## `packages/mcp`

A stdio relay that starts the exact-pinned `@mui/mcp` and copies bytes in both directions without
modification. See [packages/mcp/README.md](../packages/mcp/README.md).

## `apps/docs`

The consumer docs portal. It contains no contributor content.

- TanStack Router (file routes in `src/routes`, generated `routeTree.gen.ts`), Vite, MDX
  (`@mdx-js/rollup` with `remark-gfm`). Page content lives in `src/content`, live demos in
  `src/demos`.
- It uses `@tecton-mui/ui` through the source condition, so the portal is styled with Tecton by
  the library itself. `@tecton-mui/ui/styles/global.css` is aliased to
  `src/styles/tecton-global.css`, which has the same content taken from the package assets.
- `scripts/generate-api.mjs` generates API tables from the actual TypeScript exports with
  react-docgen-typescript (`src/generated/`, not committed). It runs before `dev`, `build` and
  `typecheck`.
- `pnpm --filter @tecton-mui/docs build` runs `vite build`, then `scripts/postbuild.mjs`. This
  prerenders every route to static HTML with a `404.html` fallback, writes `.nojekyll`, builds the
  Pagefind index and checks internal links. `DOCS_BASE=/<repository>/` sets the GitHub Pages base
  path.
- The Releases → Changelog page renders `packages/ui/CHANGELOG.md` when Changesets has created it.

## Tests and tooling

- `tests/e2e/`: Playwright specs. `tests/e2e/harness/` is a Vite app with scenarios selected by
  query string (`?scenario=…&mode=…&dir=rtl`), multiple React roots, and an `/ssr` route that
  server-renders and hydrates (`server.mjs`).
- `tooling/bundle-tests/`: `run.mjs` and a consumer fixture that resolves the built package through
  its `exports` map.
- `tooling/compatibility/`: export generator and inventory.
- `tooling/docs-sync/`, `tooling/scripts/`: manual docs sync and dependency update scripts.

See [testing.md](./testing.md).
