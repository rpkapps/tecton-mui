## Purpose

Material UI's `InitColorSchemeScript` is an inline script for server-rendered pages. Before React
loads, it reads the stored mode (`mui-mode`) and sets a color-scheme attribute on `<html>` so a theme
built with `cssVariables` and `colorSchemeSelector` paints the right colors immediately.

`@tecton-mui/ui` exports it unchanged for compatibility, but **a Tecton application does not need it**.
Light and dark mode belong to Tecton's shared theme manager: it stores the preference under
`tecton-theme-mode` and sets `data-theme` on `<html>`, which the Tecton tokens and every
`ThemeProvider` on the page follow. The Tecton theme does not use Material UI's color-scheme CSS
variables, so the attribute `InitColorSchemeScript` writes has no effect on it.

## Server rendering with Tecton

Render `TectonModeScript` in the document head instead. It runs before the first paint and applies
the stored Tecton preference, so server-rendered and static pages do not flash the wrong mode:

```tsx
import { TectonModeScript, initTecton } from '@tecton-mui/ui/styles';

// Shared by the server and client entry points.
initTecton({ defaultMode: 'light' });

export function Document({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en">
      <head>
        <TectonModeScript defaultMode="light" />
      </head>
      <body>{children}</body>
    </html>
  );
}
```

Pass the same `storageKey` and `defaultMode` to `TectonModeScript` and `initTecton`. Render the
script once, in the shell or standalone application that owns the document; hosted micro-frontends
share the shell's mode and render neither script. See [SSR Setup](/getting-started/ssr) for Emotion
and hydration details.

## When to use InitColorSchemeScript

Not in a Tecton application. Every page uses the Tecton theme, and its mode comes from the Tecton theme
manager; render `TectonModeScript` to apply it before the first paint. `InitColorSchemeScript` stays
exported only so that code written for Material UI keeps compiling.
