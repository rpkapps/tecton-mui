## Purpose

`DatePicker` lets users type a date or pick it from a calendar. It adapts to the device: a popover
calendar on desktop, a full-screen dialog on touch devices. Use `DesktopDatePicker`,
`MobileDatePicker` or `StaticDatePicker` to force one presentation (see [Variants](#variants)).

Pickers need a [`LocalizationProvider`](/guides/localization) above them. The one from
`@tecton-mui/ui` defaults to `date-fns` and `en-US`, so no adapter setup is required. Values are
native `Date` objects (or `null`).

## Variants

`DatePicker` is responsive: it renders `DesktopDatePicker` when the `desktopModeMediaQuery` (default
`@media (pointer: fine)`) matches and `MobileDatePicker` otherwise. Use a variant directly when the
presentation must not depend on the device, for example a kiosk with a touch screen and a mouse. All
three variants accept the same props.

<Demo name="DatePickerVariants" />

### Mobile dialog

`MobileDatePicker` opens a modal dialog with a toolbar and Cancel / OK buttons from the calendar
button next to the field; the field itself stays editable from the keyboard. The value is only committed when the user confirms: `onChange` follows every tap in the
dialog, `onAccept` fires once on OK. `localeText.toolbarTitle` names the dialog for screen readers.

<Demo name="MobileInspectionPicker" />

### Static calendar

`StaticDatePicker` renders the picker inline, without a field or popup. By default it uses the mobile
layout with a toolbar and action bar; `displayWeekNumber` adds ISO week numbers and
`slotProps.actionBar.actions` chooses the buttons.

<Demo name="StaticCalendarPicker" />

With `displayStaticWrapperAs="desktop"` the toolbar is dropped, so the calendar fits into a side
panel. An empty `actions` array hides the action bar and every click updates the value.

<Demo name="StaticAvailabilityPicker" />

## Controlled value

Pass `value` and `onChange` to own the state. `onChange` receives `null` when the field is cleared and
an invalid `Date` while a typed value is incomplete, so check `isNaN(value.getTime())` before saving.

<Demo name="ControlledDatePicker" />

## Validation

`minDate`, `maxDate`, `disablePast`, `disableFuture` and `shouldDisableDate` restrict the selectable
dates. `onError` reports why the current value is invalid so you can show a message.

<Demo name="ValidatedDatePicker" />

## Views: month and year pickers

`views` selects which calendar views exist and `openTo` the first one. With `['year', 'month']` the
picker returns the first day of the chosen month, which suits reporting periods.

<Demo name="ReportingMonthPicker" />

## States

Field props go through `slotProps.textField` (helper text, error, required). `readOnly` keeps the
value selectable for copying but prevents changes; `disabled` blocks all interaction.
`slotProps.field.clearable` adds a clear button.

<Demo name="DatePickerStates" />

## Customizing days

Replace the `day` slot to decorate dates, for example to mark days that have data. Build the slot on
`PickerDay` and define it at module level so its identity stays stable between renders. More day,
header, layout and action bar examples are on the [Picker Customization](/components/picker-customization)
page.

## Keyboard entry and formats

`format` sets the typing format with `date-fns` tokens; `formatDensity="spacious"` adds space around
separators. `openTo` and `reduceAnimations` tune the popup for keyboard users.

## Accessibility

- The field is keyboard-first: each part of the date (month, day, year, hours…) is a section. Arrow
  keys <kbd>Left</kbd>/<kbd>Right</kbd> move between sections, <kbd>Up</kbd>/<kbd>Down</kbd> change the
  value, digits type it directly.
- The open-picker button has an accessible label that includes the current value. In the popup,
  arrow keys move between days (or time options), <kbd>Page Up</kbd>/<kbd>Page Down</kbd> change the
  month, <kbd>Enter</kbd> selects and <kbd>Escape</kbd> closes and returns focus to the field.
- Always give the picker a `label`; describe constraints (minimum date, format) in helper text.
- Decorations added through slots (such as the report dots above) need a text alternative.
- On touch devices without a fine pointer the responsive variant opens a full-screen dialog.

## Limitations

- Date range selection is provided by the separate [range pickers](/components/date-range-pickers).
- `LocalizationProvider` is not added by `ThemeProvider`; render it yourself.
