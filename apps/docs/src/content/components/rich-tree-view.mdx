## Overview

`RichTreeView` renders a tree from data: pass an array of `items` (each with `id`, `label` and optional
`children`) and the component renders, expands and selects them. It suits large or changing
hierarchies such as asset structures, file systems or organisation charts. For small trees written in
JSX, the [Simple Tree View](/components/simple-tree-view) is simpler.

There is a single `RichTreeView` in `@tecton-mui/ui`: the MIT Community component plus features
implemented in this library. Drag-and-drop reordering, lazy loading and virtualization each turn on
with their own props; without them, the component behaves exactly like the Community one.

## Basic usage

Use `getItemId`, `getItemLabel` and `getItemChildren` when your data uses other property names.
Selection, checkboxes and expansion work as in the Simple Tree View.

## Reordering

`itemsReordering` lets users drag items: drop on the upper or lower third of an item to place it
before or after, or on the middle to nest it. `isItemReorderable` and `canMoveItemToNewPosition`
restrict moves. Keyboard users press <kbd>Alt</kbd>+<kbd>Shift</kbd> with the arrow keys; each move is
announced. Keep the new order by updating `items` from `onItemPositionChange`.

<Demo name="ReorderingTree" />

## Lazy loading

Pass a `dataSource` to fetch children when an item expands. `getChildrenCount` tells the tree which
items can be expanded (`-1` for "unknown"), and `getTreeItems(parentId)` returns the children, or
the root items when `parentId` is `undefined`. Responses are cached in memory for five minutes by
default.

<Demo name="LazyLoadingTree" />

## Virtualization

With `virtualization`, only the rows in view are mounted, which keeps trees with thousands of items
fast. The tree fills its parent, so the parent needs a height, and all rows share one height
(`itemHeight`, measured from the first row when omitted).

## Accessibility

- The tree follows the ARIA tree pattern with the same keyboard model as the
  [Simple Tree View](/components/simple-tree-view); name it with `aria-label`.
- Reorderable items describe their keyboard instructions through `aria-describedby`, and a polite live
  region announces each move. Customise the texts with `itemsReorderingLocaleText`.
- Items that are loading expose `aria-busy`; virtualized rows keep `aria-level`, `aria-posinset` and
  `aria-setsize` so screen readers still announce the position in the hierarchy.
