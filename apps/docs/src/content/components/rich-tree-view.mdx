## Overview

`RichTreeView` renders a tree from data: pass an array of `items` (each with `id`, `label` and optional
`children`) and the component renders, expands and selects them. It suits large or changing
hierarchies such as asset structures, file systems or organisation charts. For small trees written in
JSX, the [Simple Tree View](/components/simple-tree-view) is simpler.

There is a single `RichTreeView` in `@tecton-mui/ui`: the MIT Community component plus features
implemented in this library. Drag-and-drop reordering, lazy loading and virtualization each turn on
with their own props; without them, the component behaves exactly like the Community one.

## Basic usage

Use `getItemId`, `getItemLabel` and `getItemChildren` when your data uses other property names.
Selection, checkboxes and expansion work as in the Simple Tree View.

## Checkbox selection and propagation

With `multiSelect` and `checkboxSelection`, `selectionPropagation` keeps parents and children in sync:
`descendants` selects the children of a selected parent, `parents` selects a parent once all its
children are selected.

## Your data shape

`getItemId`, `getItemLabel` and `getItemChildren` read items in the shape your API returns, so there is
no mapping step. `isItemDisabled` disables items from data, here shut-in wells.

<Demo name="CustomDataShape" />

## Label editing

`isItemEditable` (a boolean or a function of the item) allows renaming: double-click the item or press

<kbd>Enter</kbd> on it, then <kbd>Enter</kbd> to save or <kbd>Escape</kbd> to cancel.
`onItemLabelChange` receives the new label so you can persist it.

<Demo name="LabelEditing" />

### Custom label input

While an item is edited, `TreeItem` renders `TreeItemLabelInput` in place of the label. Replace it
through the item's `labelInput` slot (`slotProps.item.slots.labelInput`) and render
`TreeItemLabelInput` inside your component with the props it receives: they carry the value and the

<kbd>Enter</kbd>, <kbd>Escape</kbd> and blur handling. Here the input selects the file name without
its extension when it opens, and gets an accessible name.

<Demo name="CustomLabelInput" />

## Reordering

`itemsReordering` lets users drag items: drop on the upper or lower third of an item to place it
before or after, or on the middle to nest it. `isItemReorderable` and `canMoveItemToNewPosition`
restrict moves. Keyboard users press <kbd>Alt</kbd>+<kbd>Shift</kbd> with the arrow keys; each move is
announced. Keep the new order by updating `items` from `onItemPositionChange`.

<Demo name="ReorderingTree" />

### Custom drop indicator

While an item is dragged, every item renders a `TreeItemDragAndDropOverlay` that shows where the item
would land: a line above or below the target, or a highlight when the item would become a child. The
overlay receives the drop `action` (`reorder-above`, `reorder-below`, `make-child` or
`move-to-parent`) and renders nothing without one. Replace it for every item with
`slotProps.item.slots.dragAndDropOverlay`; this example keeps the stock overlay and adds a hint that
names the action. `canMoveItemToNewPosition` keeps people inside a group, so no indicator appears
where a drop is not allowed.

<Demo name="CustomDropIndicator" />

## Lazy loading

Pass a `dataSource` to fetch children when an item expands. `getChildrenCount` tells the tree which
items can be expanded (`-1` for "unknown"), and `getTreeItems(parentId)` returns the children, or
the root items when `parentId` is `undefined`. Responses are cached in memory for five minutes by
default.

<Demo name="LazyLoadingTree" />

### Custom loading rows

While children load, the tree shows one `TreeItemLoader` row per expected child: the count from
`getChildrenCount`, or five rows when it is `-1`. The same rows fill the tree while the root items
load. `TreeItemLoader` renders a `treeitem` with the indentation and height of a real item; pass your
own content as its children and the component as `slots.itemLoader`. Spread the props it receives,
because they set the row's depth. The **Reload directory** button calls
`apiRef.current.updateItemChildren(null)`, which skips the cache and loads the tree again.

<Demo name="CustomLoadingRows" />

## Virtualization

With `virtualization`, only the rows in view are mounted, which keeps trees with thousands of items
fast. The tree fills its parent, so the parent needs a height, and all rows share one height
(`itemHeight`, measured from the first row when omitted).

## Accessibility

- The tree follows the ARIA tree pattern with the same keyboard model as the
  [Simple Tree View](/components/simple-tree-view); name it with `aria-label`.
- Reorderable items describe their keyboard instructions through `aria-describedby`, and a polite live
  region announces each move. Customise the texts with `itemsReorderingLocaleText`.
- Items that are loading expose `aria-busy`; virtualized rows keep `aria-level`, `aria-posinset` and
  `aria-setsize` so screen readers still announce the position in the hierarchy.
