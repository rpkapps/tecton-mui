## Purpose

The app bar is the strip across the top of a Tecton application: the logo and app name, the tabs
people switch between, and room on the right for the app's own buttons. In a micro-frontend setup
the shell typically owns it.

`AppBar` is the Tecton App Bar from the Figma design, the React version of the Tecton
`<wc-app-bar>` drop-in, with the same looks and behaviour. It replaces the MUI `AppBar`: there is no
`Toolbar` composition, the bar draws its own layout and your content goes into its actions region.

## Basic app bar

Select a tab, close the active one with its close button, or add one with +.

<Demo name="TectonAppBar" />

**Your page owns the data.** Each interaction calls back (`onTabSelect(id)`, `onTabClose(id)`,
`onTabAdd()`) and the page updates `tabs` and `activeTab`. The bar never changes the tabs on its
own. When the active tab is closed, select the tab before it, as the examples do.

## Branding

A Tecton icon (`logo`, suffix included, for example `map-filled`) or an image (`logoSrc`) shows next
to `appName` (default `APP`). `logo` wins over `logoSrc`; with neither, a placeholder square shows.

<Demo name="BrandingAppBar" />

## Tabs

`fixedTabs` are icon-only tabs, such as Home, before the other tabs; their `label` is the accessible
name. Each of the `tabs` has an icon, a label and optional `tags`. The active tab shows the filled
icon and a close button, unless the tab is `closeable: false`. A `disabled` tab cannot be selected.

<Demo name="TabOptionsAppBar" />

### Limiting the number of tabs

`maxTabs` hides the add button once `tabs.length` reaches the cap (`0` always hides it);
`disableTabAdd` turns it off. Add two tabs below and the + goes away; close one and it comes back.

<Demo name="TabLimitsAppBar" />

### Many tabs

When the tabs outgrow the bar, the tab strip scrolls with arrows, while the branding, the add button
and the actions keep their place. An arrow only shows while the strip can scroll its way, and is as
wide as the Home cell. A click slides the strip by the tabs that fit, and a newly selected or added
tab slides into view. Both take the theme's `transitions.duration.standard`, and with reduced
motion the strip jumps instead.

<Demo name="ManyTabsAppBar" />

## Actions

`children` render in the actions region at the right end of the bar, centred vertically. Use icon
buttons, text buttons, a menu button or an avatar; lay several out with a `Stack`. The region never
shrinks, so wide content takes room from the tabs.

## Moving from `<wc-app-bar>`

| `<wc-app-bar>`                   | `AppBar`                               |
| -------------------------------- | -------------------------------------- |
| `app-name`, `logo`, `logo-src`   | `appName`, `logo`, `logoSrc`           |
| `active-tab`, `tier`             | `activeTab`, `tier`                    |
| `max-tabs`, `disable-tab-add`    | `maxTabs`, `disableTabAdd`             |
| `.fixedTabs`, `.tabs`            | `fixedTabs`, `tabs` (same item shapes) |
| `<div slot="actions">`           | `children`                             |
| `wc-app-bar-tab-select` `{ id }` | `onTabSelect(id, event)`               |
| `wc-app-bar-tab-remove` `{ id }` | `onTabClose(id, event)`                |
| `wc-app-bar-tab-add`             | `onTabAdd(event)`                      |

## Moving from the MUI `AppBar`

The bar is built on the MUI `AppBar`, so its root props (`position`, `sx`, `className`,
`component`, `ref`) and the `MuiAppBar` theme keys still apply; `position` defaults to `static`. A
bar composed with `Toolbar` and your own title, navigation and buttons becomes `appName`, `tabs`
and `children`. `Toolbar` is still available as a general-purpose row.

## Accessibility

- Tab reaches the tab list once (on the active tab), then the active tab's close button, the add
  button and your actions. Inside the tab list, Left and Right arrow move between tabs, Home and End
  jump to the first and last, and Enter or Space selects the focused tab.
- Delete or Backspace on the active tab closes it, like its close button (announced through
  `aria-keyshortcuts`). After a tab is closed, or the add button disappears at `maxTabs`, focus
  moves to the newly active tab instead of being lost.
- The close button is a separate button next to its tab, not inside it, so screen readers and
  touch users reach it as a normal button. The tab list holds only tabs.
- The bar is a `<header>` with `role="banner"`. With two bars on a page, as in the application
  shell, give the second one an `aria-label` (or `component="nav"`) so the landmarks can be told
  apart.
- Provide a "skip to content" link before the app bar so keyboard users can bypass it, as this portal
  does.
- Icon buttons in the actions need `aria-label`s.
- With `position="fixed"`, add padding so content is not hidden behind the bar.
