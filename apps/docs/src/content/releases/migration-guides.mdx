## How upgrades are communicated

Every release of `@tecton-mui/ui` lists its changes in the [Changelog](/releases/changelog). Releases
that require changes in consuming applications get a migration guide on this page, written for
application developers: what changed, why, and the exact code to update.

The library follows semantic versioning:

- **Patch** releases fix defects and never require code changes.
- **Minor** releases add components, props or Tecton updates in a backwards-compatible way. Visual
  changes caused by a Tecton design update are announced in the changelog.
- **Major** releases may remove or rename APIs. Each one comes with a guide here.

Upgrades of the underlying MUI packages are made deliberately. When an upstream release changes
behaviour you can observe (for example a renamed prop that MUI deprecated), the change and its
replacement are listed in the release notes.

## Version guides

### 0.x (pre-release)

The `0.x` series is a pre-release line. APIs follow MUI and are not expected to change, but minor
`0.x` releases may still include breaking changes; they are called out in the changelog with upgrade
instructions. No migration guide is needed yet.
