## Where the colors come from

Tecton colors are CSS custom properties named `--tecton-color-*`. They are defined in
`@tecton-mui/ui/styles/tokens.css`, which is part of `global.css`: once for light mode, and again
under `[data-theme="dark"]` for dark mode. The theme manager sets `data-theme` on `<html>`, so every
style that reads a variable switches with the mode.

The tables on this page are generated from that stylesheet in the installed Tecton version, so they
always match what ships. The swatch next to each token uses the variable itself and follows the
portal's current mode; the **Value** column lists the value in light and in dark mode. Click a name
in the **CSS variable** column to copy it.

## Using colors

| Where                                    | Use                                     | Example                                         |
| ---------------------------------------- | --------------------------------------- | ----------------------------------------------- |
| Component props                          | The MUI color name                      | `<Button color="error">`                        |
| `sx` and `styled`, standard MUI roles    | A [MUI palette](#mui-palette) key       | `sx={{ color: 'text.secondary' }}`              |
| `sx` and `styled`, any other Tecton role | `cssVar()` from `@tecton-mui/ui/styles` | `sx={{ bgcolor: cssVar('color-bg-elevated') }}` |
| Plain CSS                                | The CSS variable                        | `color: var(--tecton-color-text-secondary);`    |

```tsx
import Box from '@tecton-mui/ui/Box';
import { cssVar } from '@tecton-mui/ui/styles';

<Box
  sx={{
    bgcolor: cssVar('color-bg-paper'),
    border: `1px solid ${cssVar('color-divider-subtle')}`,
    color: 'text.secondary',
  }}
/>;
```

`cssVar` takes the variable name without the `--tecton-` prefix (`color-bg-paper` for
`--tecton-color-bg-paper`).

### Keep the Tecton colors

Every application uses the same palette, so screens look the same wherever they come from.

- Use a token from this page; never hard-code hex, `rgb()` or named colors.
- Pick the token by its role (text, surface, action, status), not by how its value looks today: values
  change with the mode and with Tecton releases.
- Do not add colors to the theme palette or override the palette with `themeOptions`.
- If no token fits, ask the Tecton team for one instead of creating your own.

The Tecton theme fills MUI's palette from these tokens, so component `color` props and palette keys in
`sx` already use Tecton colors. The palette holds plain values (MUI's color utilities cannot read CSS
variables); the theme is rebuilt when the mode changes.

as an **Alias** under the shorter name (for example `--tecton-color-component-input-filled-background`
under `--tecton-color-input-filled-bg`). Either name works; prefer the shorter one.
