## Style entry points

Ordinary component imports never inject global CSS. Page-wide assets are explicit stylesheet
imports so that each page loads them exactly once.

| Import                                 | Contains                                                                                       | Who imports it                                  |
| -------------------------------------- | ---------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| `@tecton-mui/ui/styles/global.css`     | Tecton fonts (`@font-face`), icon classes and design tokens (CSS variables for light and dark) | The shell or a standalone app, once             |
| `@tecton-mui/ui/styles/components.css` | Static component styles; currently empty because component styles are generated by Emotion     | Hosted micro-frontends (optional)               |
| `@tecton-mui/ui/styles/fonts.css`      | Only the font faces                                                                            | Hosts that compose the global assets themselves |
| `@tecton-mui/ui/styles/icons.css`      | Only the icon classes                                                                          | Same as above                                   |
| `@tecton-mui/ui/styles/tokens.css`     | Only the design tokens                                                                         | Same as above                                   |

`global.css` is the concatenation of the three partial files. Use the partial files only if your
host already provides some of these assets, and never load an asset twice.

Importing a CSS file does not run JavaScript. The light/dark mode is applied by Tecton's theme manager,
which `initTecton()` initializes; see [ThemeProvider and shared light/dark mode](/guides/theming).

## Fonts

Tecton uses **Figtree** (a variable sans-serif font, weights 300 to 900, normal and italic) for text
and headings, and **IBM Plex Mono** for tabular data and code. The fonts are self-hosted: the font
files are bundled next to the stylesheet and referenced with relative URLs, so they load from your own
origin and work on networks that block public font services. Each face declares a `unicode-range`,
so browsers only download the subsets a page actually uses.

The `Typography` variants map to Tecton text styles. The extra `data` variant renders tabular
numerals in IBM Plex Mono.

## Icons

Icons are rendered by the `Icon` component from `@tecton-mui/ui/Icon`. Each icon is a CSS class
from `icons.css` that paints an SVG mask in `currentColor`, so icons take the text color of their
context and need no SVG imports.

```tsx
import Icon from '@tecton-mui/ui/Icon';
import Button from '@tecton-mui/ui/Button';

<Button startIcon={<Icon name="add" />}>New item</Button>;
<Icon name="warning" variant="filled" size="large" title="Warning" />;
```

- `name` is typed: your editor lists the available names and rejects unknown ones.
- `variant` is `outline` (default) or `filled`. When an icon has only one variant, that one is used.
- `size` is `xsmall` (12px), `small` (16px), `medium` (20px), `large` (24px) or `inherit` (default,
  1em of the surrounding font size).
- Without `title` an icon is decorative and hidden from assistive technologies. Add `title` when the
  icon carries meaning on its own.

A few brand marks are multicolor and ignore `variant` and the text color. The Material Icons font
and `@mui/icons-material` are not needed. MUI components that accept icons (`startIcon`,
`endIcon`, `icon`, `deleteIcon`, slots) accept `Icon` like any other element.
