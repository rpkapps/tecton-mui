# RichTreeView — feature support

`@tecton-mui/ui/RichTreeView` exports a single `RichTreeView`: the MIT MUI X Community
component (`@mui/x-tree-view` 9.18) plus advanced features implemented independently of
the commercial packages. There is no `RichTreeViewPro` export.

When you pass none of the advanced props, the component renders the Community component with
your props unchanged (same markup, same behavior). Each advanced feature turns on only through
its own props, and features can be combined.

Legend: **Supported**: works as documented. **Partial**: works with the limitations in
the notes. **Not supported**: not available.

## Limitations

- **Touch devices.** Drag and drop uses the native HTML5 API, which some mobile browsers support only partly. Keyboard reordering works everywhere.
- **Label editing while reordering.** The item content is `draggable`, so selecting text in the label input with the mouse can start a drag in some browsers.
- **No auto-expand or auto-scroll during a drag.** Hovering over a collapsed item does not expand it. Browsers auto-scroll the scroll container natively.
- **No moving between trees.** Items cannot be moved from one tree to another.
- **Lazy items and `*`.** The Community `*` key (expand all siblings) skips siblings whose children are not loaded yet.
- **Drops into unloaded items.** An item can't be dropped into a parent whose children are not loaded yet.
- **Runtime toggles.** Turning a feature on or off at runtime keeps the expansion and selection state, but remounts the items, because the item slot changes.

## Performance notes

- Drag hover state lives in an external store. Each item's drop overlay subscribes to its own key, so moving the pointer re-renders only the overlays of the previous and next targets, never the items. Tests check this.
- `slots` is stabilized with a shallow comparison, and all composed slots are module-level components, so inline `slots={{ item }}` objects do not remount items.
- Lazy loading updates only the branch it loads. A reorder or a refetch rebuilds the Community items state once per operation.
- Virtualization mounts only the rows in the window. Scrolling within the same window re-renders nothing, and each window change re-renders only the rows that enter it.
